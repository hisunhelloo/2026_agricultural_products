# 데이터 수집 결과 (2026-10-09)

공공데이터포털(data.go.kr)을 우선 조사해 실제로 다운로드까지 해본 결과를 정리한다. KAMIS는 이번 1차 수집에서는 보지 않았다 (요청에 따라 공공데이터포털 우선).

## 4차 업데이트: 기상특보(태풍·가뭄 등) 2015~2025 전체 수집 완료

기상청 API허브 `wrn_met_data.php`(기상특보 > 특보자료)로 전체 특보종류를 연도 1회 호출로 수집했다. `scripts/fetch_weather_warnings.py`, 결과는 `data/raw/kma_warnings/warnings_{연도}.csv` (11개, 총 265,107행, 18MB).

| 특보종류(WRN코드) | 건수 | 비고 |
| --- | --- | --- |
| T (태풍) | 9,702 | 태풍특보_더미 생성용 |
| D (건조) | 16,566 | 가뭄특보_더미 생성용 (기상청 체계에서 "가뭄"은 "건조특보"로 발표됨) |
| H (폭염) | 21,768 | 배추·건고추 등 여름 품목에 참고 가능 |
| R (호우) | 44,753 | |
| W/V/F/S/C/Y/O | 나머지 | 강풍/풍랑/안개/대설/한파/황사/해일 |

컬럼: `TM_FC`(발표시각), `TM_EF`(발효시각), `STN`(지점), `REG_ID`(특보구역코드), `WRN`(특보종류), `LVL`(단계), `GRD`(등급) 등. 주 단위 집계 시 "해당 주에 특정 REG_ID에서 T 또는 D 특보가 1건 이상 발효"를 더미(0/1)로 변환해서 쓰면 된다. `REG_ID`를 품목 주산지와 매핑하는 작업은 아직 안 함 (기상 관측소 선정과 같이 처리 예정).

이번엔 한 번에 11년 다 받아져서 삽질 없었음 (일별 호출이 아니라 연도당 1회라 ASOS 때 겪은 백그라운드 행 문제가 발생할 시간적 여지가 없었음).

## 3차 업데이트: 기상청 ASOS 일자료 2015~2025 전체 수집 완료

기상청 API허브(apihub.kma.go.kr, `kma_sfcdd.php`)로 전국 약 95개 관측소의 일자료를 수집했다. `scripts/fetch_weather_asos.py`로 연도별 수집, 결과는 `data/raw/kma_asos/asos_daily_{연도}.csv` (11개 파일, 총 382,145행, 100MB).

| 항목 | 내용 |
| --- | --- |
| 기간 | 2015-01-01 ~ 2025-12-31 (11개년 전체) |
| 지점 | 전국 ~95개 ASOS 관측소 (`stn=0`으로 전체 조회, 품목별 주산지 관측소는 아직 선정 전) |
| 컬럼 | TM(일자), STN(지점), TA_AVG/MAX/MIN(평균·최고·최저기온), RN_DAY(일강수량), HM_AVG(평균습도), WS_AVG(평균풍속) 등 56개 |
| 연도별 행 수 | 2015: 33,823 / 2016: 34,496 / 2017: 34,670 / 2018: 34,668 / 2019: 34,792 / 2020: 34,469 / 2021: 34,672 / 2022: 34,618 / 2023: 35,458 / 2024: 35,384 / 2025: 35,095 |

**이번에도 겪은 삽질 기록:**
- 이 API는 날짜 "범위" 조회가 안 되고 `tm=YYYYMMDD` 하루 단위로만 조회된다 (파라미터 오해로 처음엔 0건으로 받고 있었음, help=1로 스펙 재확인 후 해결).
- 수집 스크립트가 간헐적으로 완전히 멈추는 현상이 반복됐다. 원인은 이 세션의 백그라운드 실행 방식 — **포그라운드 타임아웃을 넘겨 자동으로 백그라운드 전환된 프로세스는 이후 거의 진행이 안 됨**(네트워크/타임아웃 문제가 아니라 세션 특성으로 보임). 대응: 연도 단위로 짧게 끊어 포그라운드로 돌리고, 전환되면 죽였다가 같은 명령으로 재시작하는 방식으로 우회. 이 문제 때문에 스크립트에 **일 단위 재개 기능**(`.partial`/`.progress` 파일)을 추가해, 중간에 끊겨도 처음부터 다시 받지 않게 했다.
- OneDrive 동기화가 파일을 잠깐 잠가 `PermissionError`가 난 적이 있어, 진행 마커 파일 쓰기에 재시도 로직을 추가했다.
- curl 자체 네트워크 타임아웃(`curl exit 28`)은 정상적인 간헐 현상으로, 재시도 3회 후 해당 날짜만 건너뛰는 방식으로 처리된다 (완료본에서 연도별 348~366일 중 1~5일 정도 빠졌을 수 있음, 추후 EDA에서 결측일 확인 필요).

## 2차 업데이트: 2015~2025년 장기 이력 확보 완료

오픈API(한국농수산식품유통공사_일별 도,소매 가격정보 조회, 15156057)로 **2015~2025년 전체 기간 수집에 성공했다.**
`scripts/fetch_perday_price.py`로 연도별 수집, 결과는 `data/raw/kamis_opendata/garak_perday_price_{연도}.csv` (11개 파일).

| 항목 | 내용 |
| --- | --- |
| 기간 | 2015-01-02 ~ 2025-12-31 (11개년 전체) |
| 시장 | 가락도매 (시장코드 0110211) |
| 품목 | 파(대파) 10,800 / 건고추 9,812 / 깐마늘(국산) 9,434 / 무 6,010 / 양파 5,864 / 배추 5,802 / 깐마늘(수입) 138 |
| 총 행 수 | 47,860행 |
| 컬럼 | exmn_ymd(조사일자), item_nm/vrty_nm/grd_nm(품목/품종/등급명), mrkt_nm(시장명), se_nm(구분: 중도매 등), exmn_dd_prc(조사일가격), exmn_dd_cnvs_prc(조사일kg환산가격), sgg_nm(시군구명) 등 |

**해프닝 기록 (다음에 비슷한 삽질 안 하려고 남김):** 처음엔 이 API가 날짜 범위/시장코드만 넣으면 항상 `totalCount: 0`을 반환해서 "원본 서버(agromarket.kr) 장애"로 오판했었다. 실제로는 **부류코드(`cond[ctgry_cd::EQ]`)와 품목코드(`cond[item_cd::EQ]`가 필수 파라미터**였는데 이걸 빠뜨려서 생긴 문제였다 (에러 없이 조용히 0건으로 응답되어 원인 파악이 늦어짐). data.go.kr 마이페이지의 "미리보기" 테스트 화면에서 실제로 성공하는 요청을 보고서야 원인을 찾았다. 채소류 품목은 전부 부류코드 `200`.

**남은 제약:** 지금 받은 건 가락도매 한 시장만이다. 기획서 6-5의 "원인/가격보도 기사 분리"나 품목 간 비교에는 충분하지만, 전국 시장 비교나 반입물량(공급 외생변수)은 여전히 별도 소스가 필요하다 (아래 "남은 문제" 참고).

## 핵심 결론

**공공데이터포털의 "파일데이터" 다운로드 방식으로는 기획서가 가정한 2015~2025년 장기 시계열을 확보할 수 없다.** 파일데이터는 로그인 없이 바로 받을 수 있지만, 전부 "최근 일정 기간만 담긴 롤링 스냅샷"이었다. 과거 연도별 아카이브 파일은 따로 존재하지 않았다(히스토리 버전이 1개뿐).

## 확인된 문제: 기획서에 반영 필요

- **서울 열린데이터광장 "가락시장 반입물량"(OA-13419, 기획서 5장에 공급 변수 X로 명시된 소스)이 서비스 종료 상태였다.** 페이지에 "해당 데이터는 종료된 서비스입니다"라고 표시됨. 반입물량(외생변수) 소스를 다른 데이터셋으로 교체해야 한다 — 위 2번 파일의 "조사구분명=산지"를 활용하거나, 서울 열린데이터광장의 대체 데이터셋(OA-20951 등, 서비스 상태 미확인)을 다시 찾아야 한다.
- 농넷 5품목 데이터(15087352)와 농축수산물 데이터(15072357) 둘 다 **2025년 이후로만 한정**되어 있어, 기획서가 전제한 "2015~2025, 계절 주기 여러 번"이라는 학습 조건을 만족하지 못한다. 최소 성공 기준(6장)을 이 데이터만으로 달성하려면 학습 기간을 1~1.5년으로 줄여야 하고, 이 경우 계절성 모델(SARIMA 등)의 신뢰도가 크게 떨어진다.

- 심의유형: **개발단계/운영단계 모두 자동승인** — 신청하면 즉시 키가 나올 것으로 보인다 (수동 심사 대기 없음).
- **날짜 범위를 직접 지정해서 조회 가능**: `cond[exmn_ymd::GTE]`, `cond[exmn_ymd::LTE]` 파라미터로 시작일~종료일을 YYYYMMDD로 넘긴다. 파일데이터처럼 최근 스냅샷만 주는 게 아니라, 과거 날짜를 넣으면 그 시점 데이터가 나오는 구조로 보인다 (다만 실제로 2015년까지 쌀려 있는지는 신청 후 첫 호출로 확인 필요 — 기관이 "1996년부터" 축적했다고 밝혔으므로 가능성은 높다).
- 요청 URL: `https://apis.data.go.kr/B552845/perDay/price`
- 주요 파라미터: `serviceKey`, `returnType`(JSON/XML), `pageNo`, `numOfRows`(최대 1000), `cond[mrkt_cd::EQ]`(시장코드), `cond[item_cd::EQ]`(품목코드) 등
- 응답 필드: 조사일자(exmn_ymd), 품목명(item_nm), 품종명(vrty_nm), 등급명(grd_nm), 단위(unit/unit_sz), 시장명(mrkt_nm), **조사일가격(exmn_dd_prc)**, **조사일kg환산가격(exmn_dd_cnvs_prc)** 등
- **가락도매 시장코드 = `0110211`** (코드표에서 확인. "가락소매"는 다른 코드이니 혼동 주의)
- 품목코드(참고): 배추 211, 무 231, 건고추 241, 양파 245, 깐마늘(국산) 258 / 깐마늘(수입) 259, 파(대파) 246

### 사용자가 해야 할 일 (제가 대신 할 수 없는 부분)

1. data.go.kr 로그인 → 위 URL 접속 → 우측 상단 **"활용신청"** 클릭 → 활용목적 작성 후 제출
2. 승인되면(자동승인이라 보통 즉시) 마이페이지 > 데이터활용 > Open API 이용현황에서 **일반 인증키(Encoding/Decoding)** 확인
3. 발급받은 키를 환경변수로 등록: `setx PERDAY_PRICE_SERVICE_KEY "발급받은키"` (PowerShell 새 창에서 적용)
4. `scripts/fetch_perday_price.py` 실행 (이미 작성해둠) — 먼저 최근 1개월(2026-09) 테스트 호출로 응답을 확인하고, 성공하면 스크립트 하단 주석을 풀어 2015~2025년을 연도별로 반복 수집

### 당장 할 수 있는 것 (키 승인 기다리는 동안)

지금 확보한 **2025-01 ~ 2026-06 (9~18개월)** 데이터로 EDA를 먼저 진행할 수 있다: 품목별 플롯, 위기단계명 분포, 가락도매 vs 전국 다른 시장 비교, 결측 패턴 확인.

### 남은 문제
